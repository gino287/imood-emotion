## 1. 先講一件會影響所有模型的事：架構不同，信心的行為不同

| 家族 | 我們清單上的成員 | tokenizer | 對信心的影響 |
|---|---|---|---|
| **XLM-R / DeBERTa（SentencePiece 詞級）** | `Johnson8187/Chinese-Emotion-Small`（mDeBERTa-v3-base）、`Johnson8187/Chinese-Emotion`（XLM-R large）、`xlm-roberta-base` | 子詞，多語共用 | 中文被切成較長的子詞單位；**半個詞被截斷時，tokenization 會整個改變**，信心不穩定 |
| **中文 BERT（字級 WordPiece）** | `hfl/chinese-roberta-wwm-ext`、`hfl/chinese-bert-wwm-ext`、`bert-base-chinese`、`IDEA-CCNL/Erlangshen-*` | 一字一 token | 截斷比較「乾淨」，只是少幾個字，不會改變前面的切法 |
| **英文原生 + 機翻中文** | `SchuylerH/bert-multilingual-go-emotions`、`monologg/GoEmotions-pytorch` | — | 中文是機翻資料訓練的，**信心在中文上的意義存疑，需獨立驗證** |

### 順手查證：現行模型的真實身世

從本機 HF 快取的 `config.json` 讀出來（不是猜的）：

```json
"_name_or_path": "MoritzLaurer/mDeBERTa-v3-base-mnli-xnli",
"architectures": ["DebertaV2ForSequenceClassification"],
"model_type": "deberta-v2",
"num_hidden_layers": 12, "hidden_size": 768,
"id2label": { "0": "LABEL_0", ... }        ← 果然只有佔位符
```

兩個值得記住的點：

1. **底層是 `mDeBERTa-v3-base-mnli-xnli`** —— 也就是一個
   **先在 XNLI（跨語言自然語言推論）微調過的模型**，
   再被 Johnson 拿去微調成情緒分類。
   不是從乾淨的 mDeBERTa 開始的。這種「二手微調」的模型，
   信心分布會帶著上一個任務的痕跡，是它校準行為的一個可能來源。
2. **12 層 / hidden 768**，但 fp32 佔 1.08GB —— 因為 mDeBERTa 的多語詞表很大
   （embedding 就佔掉大半）。**這也是為什麼 fp16 省下的 VRAM 特別有感。**

> ⚠️ 另外重申一筆記憶裡的事實：
> baseline `Johnson8187/Chinese-Emotion`（large 版）**是 XLM-RoBERTa 家族**
> （SentencePiece 詞級 tokenizer，不是字級 BERT），且 config 同樣沒有 id2label。
> 這代表 **它跟 `hfl/chinese-roberta-wwm-ext` 之間的比較，不只是「大小不同」，
> 連 tokenization 粒度都不同** —— 截斷穩定度的比較上，這是一個真正的變因。

### 一個可以做的實驗（成本低、還沒做）

> **同一批截斷片段，比較「字級 BERT」與「詞級 XLM-R」的翻類率。**
> 假設是字級模型比較穩（因為截斷不會改變前面的切法）。
> 如果成立，這對「最終選哪個基底模型」是一個新的、跟速度/準確率無關的評選維度。
> 成本：`hfl/chinese-roberta-wwm-ext` 沒有情緒 head，要先微調——所以其實不便宜。
> 折衷做法：先只比 tokenization 的穩定度（不需要 head），
> 量「完整句 vs 片段的 token 序列前綴一致率」，這個零成本。

## 2. GoEmotions 系模型的特別注意事項：多標籤 ≠ 多類

`SchuylerH/bert-multilingual-go-emotions` 與 `monologg/GoEmotions-pytorch`
是 **multi-label**（一句可以同時是 joy 和 excitement），
所以它們用的是 **sigmoid 不是 softmax**：

```python
# 多類（我們現在的模型）
probs = torch.softmax(logits, dim=-1)   # 加總 = 1
# 多標籤（GoEmotions 系）
probs = torch.sigmoid(logits)           # 每一格獨立，加總 ≠ 1
```

**這完全改變 confidence 的意義**：

| | softmax（多類） | sigmoid（多標籤） |
|---|---|---|
| 「0.9」的意思 | 在 K 個候選裡佔 90% 票數 | 這一個標籤獨立成立的機率 0.9 |
| 可以「全部都低」嗎 | ❌ 至少有一格 ≥ 1/K | ✅ 可以全部 < 0.1（= 「都不是」）|
| 可以「多個都高」嗎 | ❌ | ✅ |

> **這是一個實質優勢**：sigmoid 模型 **天生有「以上皆非」這個出口**，
> 而 softmax 沒有（見 01 篇）。如果哪天需要偵測「這句沒有明顯情緒」或
> 「這句是 STT 幻覺」，多標籤模型在結構上做得到，softmax 模型做不到。
>
> 但代價是：`{ts, text, emotion, confidence}` 這個下游格式要重新定義
> （emotion 可能有 0 個或多個），而且 `confidence` 的門檻要重新校準
> ——**sigmoid 的 0.5 跟 softmax 的 0.5 完全不是一回事**。
>
> → 值得記進 backlog：如果之後真的要處理「無情緒/幻覺」，
>   選多標籤模型可能比在 softmax 上加門檻更根本。

## 3. 怎麼查：三種深淺不同的做法

### 3.1 最快：直接看完整分布（我們已經存了）

```python
from imood_emotion.classifier import EmotionClassifier

clf = EmotionClassifier(device="cpu")
clf.load()
p = clf.predict("你怎麼這麼討厭啊")

print(f"{p.label}  {p.confidence:.4f}")
for lab, v in sorted(p.probs.items(), key=lambda kv: -kv[1]):
    print(f"  {lab:6} {v:.4f} {'█' * int(v * 40)}")
```

### 3.2 從既有的 jsonl 重算，不用跑模型

所有分析（ECE / 溫度 / AUROC / 風險-覆蓋率）都能從
`probs` 這一欄重算。這正是 `exp_calibration.py` 在做的事。
**換映射、換指標、換門檻，都不需要重跑模型。**

```bash
docker compose -f docker/docker-compose.yml run --rm app-cpu \
    python research/confidence/experiments/exp_calibration.py
```

### 3.3 要拿到 logits（目前拿不到，但只差一行）

energy score 這類方法需要 logits 的絕對尺度，softmax 之後就沒了。
`classifier.py` 的 `predict()` 現在是：

```python
logits = self.model(**enc).logits
...
probs = torch.softmax(logits, dim=-1)[0].tolist()
```

`logits` 已經在手上，只是沒存。加一欄 `raw_logits` 成本近乎 0
（8 個 float，jsonl 每行多約 80 bytes），就打開了：

- **energy score** `-logsumexp(z)` —— OOD 偵測普遍比 MSP 好
- **溫度縮放不用繞路**（現在是用 `log(p)` 還原等價 logits，正確但多一層）
- **之後換模型時的 logit 尺度比較**

> 建議：**做**。這是整份調查裡 CP 值最高的程式改動。

## 4. 換模型時，信心值有哪些東西「不能沿用」

這點很重要，因為評測框架設計成「加一段 yaml 就能加模型」，
很容易誤以為信心相關的設定也能沿用：

| 東西 | 能不能跨模型沿用 | 原因 |
|---|---|---|
| 映射表 | ✅ 同系列可以（Johnson small/large 原生類別相同） | 類別集合相同 |
| **溫度 T** | ❌ **絕對不能** | T 是那個模型在那份資料上的擬合值 |
| **信心門檻 τ** | ❌ **絕對不能** | 不同模型的分數分布完全不同 |
| ECE / AUROC 數字 | ❌ 只能當同條件下的對照 | — |
| 「0.9 很高」這種直覺 | ❌ | 有些模型平均信心 0.6，有些 0.95 |

> **實作建議**：如果之後真的要在 production 用門檻，
> 那個門檻應該跟 `MODEL_REVISION` 綁在同一個地方（`labels.py` 或 config），
> 讓「換模型忘了換門檻」變成不可能，而不是靠記得。
> 這跟現有的「版本釘選」決策是同一個精神。

## 5. 對現行 `decisions.md` 兩條決策的直接建議

### 5.1 「反差感/情緒強度 → 用信心分數處理」

> 現行文字：「屬於 Emotion Video Selector 的下游工作，用信心分數處理，BERT 不用解決」

**建議修正**：`confidence` 不是強度。
- 「我超級無敵開心！！！」與「還行啦，有點開心」可以有一樣的 0.95
- 信心回答的是「我多確定是這一類」，不是「這個情緒有多強」

如果下游真的需要強度，可能的來源：
1. **語音端的聲學特徵**（音量、音高變異、語速）——Moshi 那邊有音訊，這才是強度的自然來源
2. **文字端的強度詞/標點**（「超」「爆」「！！！」）——規則就能做
3. **訓練一個 regression head** ——要資料，成本高

→ 短期建議：**把 confidence 傳下去沒問題，但要在介面文件寫清楚它是「分類把握度」，
  不是「情緒強度」**，避免下游拿它當強度用。

### 5.2 「下游精簡輸出格式 `{ts, text, emotion, confidence}`」

⚠️ **先承認現有決策是有道理的。** `downstream.py` 的 docstring 寫得很清楚：

> 「格式刻意只有四個欄位。品靜那邊的實際需求還沒定案，先給最小可用集合，
>  不預先設計還沒被提出的需求 —— 加欄位很容易，拿掉已經被依賴的欄位很難。」

這個原則是對的，所以下面是 **建議、不是主張現在就改**。
要不要加，取決於「這兩個欄位是不是在解一個已知存在的問題」——
我認為 `runner_up` 是（angry↔sad 混淆已經是已知問題），`margin` 比較邊緣。

**可考慮增加的欄位**（成本近乎 0）：

```jsonc
{
  "ts": ...,
  "text": ...,
  "emotion": "angry",
  "confidence": 0.83,      // = max(probs)，分類把握度，不是強度
  "margin": 0.41,          // 第一名 - 第二名。「在兩類間猶豫」的訊號
  "runner_up": "sad",      // 第二名是誰。angry↔sad 混淆是已知問題，
                           // 下游知道第二名是 sad 可以選比較安全的影片
  "final": true            // 來自 STT 的 SEND_FINAL，不是模型算的
}
```

`runner_up` 特別值得加：既然已知「憤怒常被誤判成悲傷」，
下游拿到「emotion=sad, runner_up=angry」時，可以選一支
「對兩種情緒都不會太錯」的影片，而不是全押在 sad 上。
這比設信心門檻實用得多，而且完全不需要模型變好。

## 6. 針對「憤怒準確率只有 60%」這件事，信心能幫上什麼

實測（A 組，同領域）：

```
憤怒語調   預測 18 次   平均信心 0.785   精確率 0.722
（八類中信心最低，也是精確率最低的兩類之一）
```

**好消息：模型自己知道它對憤怒沒把握。**
其他類的平均信心都在 0.86~0.97，憤怒是 0.785，明顯低一截。

這代表兩件事：

1. **per-class 門檻是有依據的**：對憤怒用較低的門檻（因為它本來分數就低），
   對疑問用較高的門檻（因為它高估最多，+0.206）。
   ⚠️ 但 A 組每類只有 18~36 句，**現在還不能定門檻值**，
   要更大的樣本才有意義。
2. **與其設門檻，不如用 `runner_up`**：憤怒被誤判成悲傷/厭惡時，
   正確答案很可能就在第二名。把第二名傳給下游的資訊量，
   比「信心 0.78，你自己看著辦」大得多。

## 7. 一頁式行動清單

| 動作 | 檔案 | 成本 | 優先 |
|---|---|---|---|
| `predict()` 多存 `raw_logits` | `imood_emotion/classifier.py` | 一行 | 🔴 |
| 下游格式加 `margin` / `runner_up` | `imood_emotion/downstream.py` | 小 | 🔴 |
| 介面文件註明 `confidence ≠ 情緒強度` | 介面規格 / decisions.md | 0 | 🔴 |
| 用修正版說法跟品靜溝通截斷這件事 | — | 0 | 🔴 |
| 蒐集 100~200 句真實 STT 口語並標註 | 新工作 | 半天 | 🟡 |
| 比較字級 vs 詞級 tokenizer 的截斷穩定度（只比 token 前綴，不跑模型） | 新腳本 | 小 | 🟡 |
| 若之後要處理「無情緒/幻覺」→ 考慮多標籤模型而非 softmax 門檻 | backlog | — | 🟢 |
| per-class 門檻 | — | — | 🟢 樣本不夠，先別做 |
