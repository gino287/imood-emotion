# 05 — 比「設門檻」更適合本專案的三個做法

> 03 篇的結論是「門檻在我們的場景很難用」。
> 那不用門檻要用什麼？這一篇整理三個 **對即時串流情緒特別對症** 的做法，
> 都不需要模型變好、也不需要重訓。

---

## 為什麼「單句門檻」在我們的場景先天不利

單句門檻的隱含假設是：**每一句是獨立事件，錯了就丟掉，丟掉是安全的。**

我們的場景三個假設都不成立：

1. **不獨立**：使用者的情緒是連續的。上一句是 sad，這一句多半也是 sad。
   單句獨立判斷等於把最有用的先驗丟掉。
2. **不能丟**：JoyGen 需要持續有情緒可以演。棄權不是「不動作」，
   是「用上一個」或「退回中性」——那本身也是預測，也會錯（03 篇 2.3 節）。
3. **時間軸上錯得不對稱**：情緒 **偶爾跳錯一句** 跟 **持續錯 5 秒** 對使用者的體感
   差非常多。前者可能根本沒人察覺，後者是明顯的「這個 AI 不懂我」。
   **單句準確率量不到這個差別。**

→ 所以應該從「這一句對不對」轉向 **「這段時間的情緒軌跡對不對」**。

---

## 做法一：時間平滑（temporal smoothing）

### 概念

不要每句都直接輸出，而是把最近幾句的機率向量做加權平均再取 argmax。

```python
# 指數移動平均（EMA）：最簡單也最常用
smoothed = alpha * current_probs + (1 - alpha) * smoothed
emotion = argmax(smoothed)
```

- `alpha` 大 → 反應快、抖動多
- `alpha` 小 → 穩定、但情緒轉折會延遲

### 為什麼特別適合我們

- **零成本**：8 個 float 的加權平均，遠小於 1ms。
- **直接解決已知問題**：「憤怒被讀成悲傷」如果只是偶發單句誤判，
  平滑會把它吃掉；如果是持續誤判，那平滑也擋不住——
  **這反而是個好的診斷工具**：平滑後還在錯的，才是真的錯。
- **文獻支持**：語音情緒辨識領域的標準做法。
  搜到的做法包括 Kalman filter（把情緒當連續狀態）與 median smoothing
  （最輕量、對單點離群值特別有效）。

### 要注意的

- **會增加延遲感**（不是計算延遲，是「情緒反應延遲」）。
  使用者突然生氣，系統要幾句之後才跟上。
  在情緒陪伴場景，這個 trade-off 要實際體驗過才知道能不能接受。
- **`alpha` 該設多少沒有理論答案**，要用真實對話試。
- 平均的應該是 **機率向量** 不是 **標籤**。平均標籤（投票）會丟掉信心資訊。

### 建議

**這是最值得先做的一個**：成本近乎零、直接對應「反差感/情緒穩定度」，
而且做完之後才有辦法判斷「憤怒 60%」到底是抖動還是真的分不出來。

---

## 做法二：遲滯（hysteresis）—— 切換要比維持更難

### 概念

不要用同一個門檻決定「進入某個情緒」和「離開某個情緒」：

```
維持目前情緒：只要它的機率 > 0.3 就繼續
切換到新情緒：新情緒的機率要 > 0.6 才切
```

這是控制系統裡防止 chattering（在邊界上來回跳）的標準手法，
跟溫控器不會在設定溫度上反覆開關是同一個道理。

### 為什麼適合我們

- **JoyGen 切換影片是有成本的**（畫面跳動、不自然）。
  情緒在 sad/angry 之間每句跳一次，比一直維持 sad 還糟。
- 遲滯把「切換成本」明確編碼進決策裡，而單一門檻做不到。
- 一樣是零計算成本。

### 跟平滑的關係

**兩者互補，不是二選一**：
平滑處理「機率的雜訊」，遲滯處理「決策的抖動」。
可以先 EMA 平滑，再對平滑後的機率套遲滯。

## 做法三：把成本寫進門檻（cost-sensitive threshold）

如果最後還是要設門檻，至少 **不要憑感覺設 0.8**。

決策理論給的答案很簡單：門檻應該來自 **錯誤的相對成本**。
二元情況下：

```
t* = C_FP / (C_FP + C_FN)
```

多類 + 棄權的一般形式是最大化期望效用：

```
決策 = argmax_d  Σ_y  p(y|x) · U(y, d)
```

其中 `U(y, d)` 是「真實情緒是 y、系統選了 d」的效用。

### 對我們的具體含意

這個框架逼你回答一個目前 **還沒有人回答過** 的問題：

> **「使用者在生氣、系統演成悲傷」跟「使用者在生氣、系統演成中性」，
>  哪一個比較糟？糟多少？」**

`open_questions.md` 裡有一句：

> 「對情緒陪伴場景，『使用者在生氣』被讀成『在難過』會選到完全相反的回應影片，
>  比整體準確率的小數點更值得追蹤。」

**這句話其實就是在說「U(angry, sad) 特別低」**，只是還沒量化。
一旦寫成一個 6×6 的效用矩陣（大部分格子可以先填 0/-1 的粗略值），
就能：

1. 算出 **每個類別各自的最佳門檻**，而不是全域一個數字
2. 用「期望效用」取代「準確率」當作評測主指標——
   這比 Macro-F1 更貼近「使用者體感好不好」
3. 讓「厭惡→fear 還是 →angry」那個映射爭議 **有客觀依據可以結案**
   （哪個映射的期望效用高就選哪個）

### ⚠️ 但這需要 leader / 產品端拍板

效用矩陣不是技術問題，是產品決策：「演錯成中性」跟「演錯成相反情緒」
哪個比較不能接受，只有定義體驗的人能決定。

→ **建議做法**：不要等 leader 主動給。
自己先填一版粗略的（例如「相反情緒 = -2、無關情緒 = -1、中性 = -0.5、正確 = +1」），
拿去問「這樣對嗎」。**給一版草稿讓人改，比開放式問問題有效率得多。**

## 三者的關係與建議順序

```
原始機率向量
    │
    ├─(1) EMA 平滑 ────→ 降低雜訊              零成本，先做
    │
    ├─(2) 遲滯 ────────→ 降低切換抖動          零成本，接著做
    │
    └─(3) 效用矩陣 ────→ 決定門檻/映射/評測指標  需要產品端拍板
```

| 做法 | 計算成本 | 需要誰同意 | 解決什麼 | 優先 |
|---|---|---|---|---|
| EMA 平滑 | ~0 | 自己 | 單句抖動 | 🔴 先做 |
| 遲滯 | ~0 | 自己 | 情緒來回跳 | 🔴 接著做 |
| 效用矩陣 | ~0 | leader/產品 | 門檻該多少、映射選哪個、用什麼指標評 | 🟡 需要先問 |
| 單句信心門檻 | ~0 | 自己 | （在我們場景效果差） | ⚪ 不建議單獨用 |

## 一個延伸的評測想法

現有評測全部是 **單句準確率**。上面三個做法改善的是 **序列品質**，
用單句準確率量不出來（甚至可能因為平滑延遲而略微下降）。

要量到它們的好處，需要一個 **序列層級的指標**，例如：

- **切換次數 / 分鐘**（越少越穩，但太少代表沒反應）
- **情緒段落的平均長度**
- **「相反情緒」錯誤的比例**（用效用矩陣加權）
- **反應延遲**：真實情緒轉折發生後，幾句之內系統跟上

⚠️ 這需要 **有時間軸標註的對話資料**，我們現在沒有。
`models_datasets.md` 候選清單裡的 `CPED` / `M3ED` / `IEMOCAP` 都是對話級資料集，
如果要走這條路，這幾個值得優先看。
