# 06 — 如果走微調路線：訓練階段能為信心值做什麼

> `decisions.md`：「是否微調 → 條件式：先接通 pipeline 看實際效果，效果不夠才回頭微調」。
> 這一篇是為「真的要微調」那天先備好的筆記，**現在不用做任何事**。

---

## 1. 一個現在就該知道的事實：多語言模型的校準天生比較差

搜到的研究指出：

> **多語言模型即使在其他語言上準確率不錯，校準卻很差——
> ECE 在英文與非英文之間可以翻倍（XQuAD zero-shot 從 7.3% 變成 18%）。**
> 校準誤差與「語言距離」正相關，與「該語言在預訓練語料中的佔比」反相關。

**這對我們的模型清單直接有影響**：

| 模型 | 類型 | 預期校準 |
|---|---|---|
| `Johnson8187/Chinese-Emotion-Small`（mDeBERTa-v3-base） | **多語言** | ⚠️ 中文在多語語料中佔比不高，校準可能偏差 |
| `Johnson8187/Chinese-Emotion`（XLM-R large） | **多語言** | ⚠️ 同上 |
| `xlm-roberta-base` | **多語言** | ⚠️ 同上 |
| `hfl/chinese-roberta-wwm-ext` | **純中文** | ✅ 預期較好 |
| `hfl/chinese-bert-wwm-ext` | **純中文** | ✅ |
| `bert-base-chinese` | **純中文** | ✅ |
| `IDEA-CCNL/Erlangshen-*` | **純中文** | ✅ |

> **這是一個「換基底模型」的新論據**，而且是原本沒被列入考量的維度。
> 現有的比較維度是「速度 / 準確率 / VRAM」，
> **「校準品質」可以加進去** —— 特別是如果下游真的要用 confidence 做決策的話。
>
> ⚠️ 但這是文獻上的一般結論，**沒有在我們的任務上驗證過**。
> 而且純中文模型都沒有情緒 head，要比較就得先各自微調一輪，成本不低。
> 建議：**先不要為了校準去換模型**，等有微調需求時，
> 把「校準」列入評選表的一欄，順便量就好。

## 2. 微調時的 loss 選擇：focal loss 目前是最佳解

如果要微調，loss 的選擇直接決定校準品質。文獻結論相當一致：

| Loss | 同領域校準 | 跨領域校準 | 對分布偏移的敏感度 |
|---|---|---|---|
| **Cross-Entropy**（預設） | 差（會過度自信） | 差 | 低 |
| **Label Smoothing** | 比 CE 好 | **最好** | 中 |
| **Focal Loss** | **最好** | 好 | **最好**（FAR95 最低） |
| Brier / MMCE | 中 | 中 | — |

主要依據：

- 《Calibrating Deep Neural Networks using Focal Loss》：
  > 「用 focal loss 訓練的網路，校準比 cross-entropy（含加 label smoothing）、
  >  MMCE、Brier loss 都好。」
- 《Uncertainty Quantification with Pre-trained Language Models》大規模實證：
  > 「Focal Loss 是預訓練語言模型 pipeline 最有說服力的微調 loss，
  >  在領域內與領域外都有具競爭力的低 ECE。」
  > 「用 CE 或 focal loss 微調的模型在領域內校準較好，
  >  **label smoothing 則在領域外的 ECE 有下降**。」
  > 「Focal Loss 微調的模型 FAR95 最低，代表對領域偏移最敏感（= 最會示警）。」

### 對我們的建議

**如果哪天微調，直接用 focal loss，不要用預設的 CrossEntropyLoss。**
理由：
1. 校準比較好，**而且不用付出準確率的代價**（文獻上通常持平或略好）
2. 對分布偏移比較會示警——我們的真實場景就是持續的分布偏移
3. 實作成本近乎 0（HuggingFace `Trainer` 覆寫 `compute_loss` 即可）

⚠️ focal loss 的 γ 是超參數（常用 2 或 3），要調。
`AdaFocal` 是自動調 γ 的版本，如果懶得調可以看那個。

## 3. 訓練資料層面：soft label

01 篇提過情緒標註的分歧率極高（EmotionLines：72.6% 語句有分歧、
14.3% 沒有多數決）。文獻上的處理方式：

> 「soft-label learning 把訓練目標改成『逼近標註者的實際分布』，
>  而不是逼近一個 one-hot。」
> 「額外的標註者資訊（信心、次要標籤、分歧程度）可以有效產生 soft label，
>  **用這些 soft label 訓練的分類器表現更好**。」

**問題是：我們的資料集沒有多標註者資訊。**
`SMP2020-EWECT` 與 `Johnson8187` 那份都只有單一標籤。

如果之後真的要自己標資料（例如標 100~200 句真實 STT 口語，
見 `RESULTS.md` 的行動清單），**建議一開始就設計成多標註者 + 保留分布**：

- 找 3 個人各標一次，保留三個人的答案而不是投票
- 或至少讓標註者填「主要標籤 + 次要標籤 + 有多確定」
- 這份資料同時能拿來：①配溫度 ②量真實 ECE ③當 soft label 微調用
  ④算「人類自己的一致率」——那才是準確率的真正天花板

> **這最後一項特別重要**：如果三個人對同一批句子只有 70% 一致，
> 那模型 85% 準確率其實已經超過人類共識了，
> 「憤怒只有 60%」也許有一大半是題目本身的問題。
> **在標註之前，我們沒辦法區分「模型爛」和「題目沒有唯一答案」。**

## 4. 微調對「即時性」的影響（別忘了硬需求）

微調 **不會改變推論速度**（架構沒變）。所以微調路線與 GPU 熱啟動那條線
完全獨立，不衝突。

唯一要注意的是：如果微調時 **換了更大的基底**（例如
`Johnson8187/Chinese-Emotion` 是 XLM-R large ~355M，
現在用的 Small 是 mDeBERTa-v3-base ~0.3B），
那速度會變，要重跑延遲量測。

---

## 5. 一頁式：微調那天的檢查清單

- [ ] loss 用 **focal loss**（γ 從 2 開始試），不要用預設 CE
- [ ] 如果目標是跨領域校準，**額外試 label smoothing** 作為對照
- [ ] 基底模型的評選表加一欄「校準（ECE / AUROC）」
- [ ] 如果自己標資料，**設計成多標註者、保留標籤分布**
- [ ] 微調後 **一定要重新配溫度、重新定門檻**（04 篇第 4 節）
- [ ] 微調後重跑延遲量測（如果換了基底大小）
